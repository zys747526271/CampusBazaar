# 03 · 角色与权限设计

## 1. 三角色模型

```
                  ┌──────────────┐
                  │   用户 User   │
                  │ role / roles[]│
                  └──────┬───────┘
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   学生买家 buyer   学生卖家 seller   管理员 admin
   浏览/购买/评价    发布/发货/经营     审核/封禁/统计
```

## 2. 权限矩阵（目标设计）

| 能力 | 学生买家 | 学生卖家 | 管理员 |
| --- | :---: | :---: | :---: |
| 浏览/搜索商品 | ✅ | ✅ | ✅ |
| 加入购物车 / 下单支付 | ✅ | ✅ | ✅ |
| 评价已购商品 | ✅ | ✅ | ✅ |
| 发布商品 | ❌ | ✅（需审核） | ✅ |
| 管理自己的商品/库存 | ❌ | ✅ | ✅ |
| 发货（自己订单项） | ❌ | ✅ | ✅ |
| 审核商品上架 | ❌ | ❌ | ✅ |
| 封禁用户/卖家 | ❌ | ❌ | ✅ |
| 分类/标签/VIP/广告管理 | ❌ | ❌ | ✅ |
| 平台订单监管/数据统计 | ❌ | ❌ | ✅ |

## 3. 当前实现状态

- 后端已有 4 个鉴权装饰器（`backend/utils/decorators.py`）：
  - `token_required`：任意已登录用户
  - `login_required`：普通学生用户
  - `admin_required`：管理员
  - `super_admin_required`：超级管理员（**当前实现有 bug**：中文枚举 `'普通'/'超级'` 与整数比较，必然失败）
- `Product` 的 `seller_id` 已建立"用户即卖家"的关系，但**没有单独的卖家准入校验**——任何登录用户都能调用创建商品接口。
- 管理员注册接口 `POST /api/auth/admin/register` 当前**无需任何审批**，生产环境必须关闭或加邀请码/审批流。

## 4. JWT 载荷建议

```json
{
  "user_id": 123,
  "type": "user",          // user | admin
  "roles": ["buyer", "seller"],
  "exp": 1735689600
}
```

- 统一用 `user_id` + `roles[]`，弃用当前 `type` 双表判断，避免 ID 碰撞。
- 每次请求从数据库读取最新 `is_banned`/`is_deleted` 状态，防止封禁后旧 token 仍可用。
- 敏感操作（改密、提现、审核）要求短效 token 或二次验证。

## 5. 前端路由守卫

`frontend/src/router/index.js` 已有基础守卫（读 localStorage 的 token 与 `userInfo.isAdmin`）。扩展方向：

- 路由元信息 `meta: { roles: ['seller','admin'] }`，配合 `beforeEach` 做角色校验。
- 菜单按角色动态渲染：买家看到商城/订单，卖家额外看到"我的店铺/发布商品"，管理员看到"管理后台"。
- 修复 LoginPage 登录后未写入 `userInfo` 导致管理员判断失效的问题。
