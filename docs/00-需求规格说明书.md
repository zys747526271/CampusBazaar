## 1. 项目概述

### 1.1 背景

校园内的二手教材、数码、生活用品交易长期依赖微信群与公告板，存在四个结构性痛点：

1. **信息易沉底**：群消息滚动后商品信息不可检索，同一件物品被反复询问。
2. **交易无凭证**：口头约定，无订单记录，出现纠纷无法追溯。
3. **信任成本高**：无卖家历史、无评价体系，买家只能凭感觉判断。
4. **履约无状态**：付款、交付、确认全靠私聊，容易漏单、扯皮。

### 1.2 产品定位

面向单一高校（或校区联盟）的**校内 C2C 二手交易平台**：学生既是买家也可以是卖家，平台提供商品发布、检索、下单、履约、评价的完整链路，并对内容与交易做基础治理。

**与淘宝/京东的差异**（决定了很多设计取舍）：

| 维度 | 综合电商       | 本项目                    |
| -- | ---------- | ---------------------- |
| 卖家 | 专业商家       | 学生个人，卖自己用过的物品          |
| 履约 | 快递 + 平台物流  | 校内自提（当面验货）为主，可选快递     |
| 商品 | 标准化 SKU、海量 | 非标、单品、库存通常为 1          |
| 支付 | 平台担保交易     | 首版线下/转账 + 平台记账，后续接担保支付 |
| 治理 | 强审核 + 客服体系 | 轻审核 + 举报 + 管理员抽检       |

### 1.3 目标

| 编号 | 目标                      | 衡量方式                |
| -- | ----------------------- | ------------------- |
| G1 | 买家 3 分钟内完成"找商品→下单"      | 关键路径埋点，中位耗时 ≤ 3 min |
| G2 | 卖家 5 分钟内完成"成为卖家→发布首个商品" | 发布漏斗埋点              |
| G3 | 交易全流程线上留痕，可追溯           | 每笔订单有状态流转记录与操作者     |
| G4 | 违规内容可被快速处置              | 举报到隐藏的处理时长 ≤ 24 h   |
| G5 | 同一套代码同时支撑本地演示与生产部署      | 配置驱动，不改代码           |

### 1.4 非目标（本期明确不做）

- 不做多校区多租户 SaaS（预留 `campus_id` 字段，但不实现隔离逻辑）。
- 不做直播、拼团、秒杀、优惠券叠加等营销玩法。
- 不做自建支付通道；首版仅支持"余额支付 + 线下支付记账"，真实支付走第三方托管接口预留。
- 不做即时通讯（IM）；站内消息为异步通知，不做会话。
- 不做 App / 小程序客户端，仅 Web（移动端自适应）。

## 2. 用户与角色

### 2.1 用户画像

| 角色           | 画像                | 核心诉求               | 痛点                     |
| ------------ | ----------------- | ------------------ | ---------------------- |
| 买家（学生）       | 大二/大三，预算敏感，习惯手机浏览 | 快速找到便宜好用的二手物品，交易安全 | 怕被骗、怕白跑、怕信息过期          |
| 卖家（学生）       | 毕业季/换季清理物品        | 快速出手，少沟通成本         | 反复回答"还在吗"、被砍价骚扰、发布流程繁琐 |
| 管理员（运营/指导教师） | 兼职运营，非专职客服        | 快速处理违规、掌握平台数据      | 缺少批量工具、缺少证据链           |

### 2.2 关键场景

**S1 · 买家捡漏**：首页看到"最新上架" → 点分类"教材" → 列表按价格升序 → 进详情看实拍图与卖家信誉 → 加购物车 → 选地址下单 → 线下自提后确认收货 → 评价。

**S2 · 卖家清仓**：登录后点"我要卖" → 一次性开通卖家身份 → 发布商品（拍照上传、选自己的分类、填库存 1）→ 在卖家中心看待审核状态 → 通过后收到订单 → 发货/约自提 → 完成。

**S3 · 管理员处置**：收到举报 → 在管理后台按卖家筛商品 → 查看该商品评论 → 隐藏含联系方式的评论 → 下架违规商品 → 记录处置原因。

**S4 · 本地演示**：评委/老师拿到项目 → 执行一条命令 → 自动建库、灌演示数据、打印测试验证码 → 浏览器直接可用三角色账号体验。

### 2.3 角色与权限矩阵

权限粒度到"操作"，`本人` 表示仅限资源所有者。

| 能力         | 游客  | 买家     | 卖家       | 管理员       |
| ---------- | --- | ------ | -------- | --------- |
| 浏览首页/列表/详情 | 允许  | 允许     | 允许       | 允许        |
| 搜索、按分类筛选   | 允许  | 允许     | 允许       | 允许        |
| 查看评价       | 允许  | 允许     | 允许       | 允许（含已隐藏）  |
| 注册/登录      | 允许  | —      | —        | 独立入口      |
| 收藏、浏览记录    | 需登录 | 本人     | 本人       | —         |
| 加购物车、下单    | 需登录 | 本人     | 本人       | —         |
| 发布/编辑/下架商品 | 禁止  | 需先开通卖家 | 本人       | 全部        |
| 管理自定义分类    | 禁止  | 需先开通卖家 | 本人       | 全部        |
| 查看收到的订单、发货 | 禁止  | 禁止     | 本人       | 全部        |
| 评价商品       | 禁止  | 已购订单   | 已购订单     | —         |
| 商品审核、下架    | 禁止  | 禁止     | 禁止       | 允许        |
| 隐藏/恢复评价    | 禁止  | 禁止     | 禁止（仅可举报） | 允许        |
| 封禁用户       | 禁止  | 禁止     | 禁止       | 允许        |
| 查看经营统计     | 禁止  | 禁止     | 本人       | 全站        |
| 管理员注册      | 禁止  | 禁止     | 禁止       | 需开关 + 邀请码 |

**权限实现约束**：

1. 后端为唯一裁决点，前端隐藏入口只做体验优化，不作为安全边界。
2. 鉴权失败必须区分语义：**401 = 未认证/令牌无效**，**403 = 已认证但无权限**。前端只对 401 清理登录态，403 仅提示。
3. 管理端与用户端使用**独立令牌与独立存储键**（`admin_token` / `token`），互不覆盖。
4. 所有"本人"资源必须在服务端校验归属，禁止只靠前端传 `user_id`。

## 3. 业务规则

### 3.1 核心领域对象

```
用户 User ──1:N── 商品 Product ──1:N── 评价 Comment
   │                 │
   │                 └──N:1── 分类 Tag（平台）/ SellerCategory（卖家）
   ├──1:N── 购物车 Cart ──N:1── 商品
   ├──1:N── 订单 Order ──N:M── 商品（下单快照）
   ├──1:N── 地址 Address
   ├──1:N── 收藏 Favorite / 浏览记录 BrowseHistory
   └──1:1── 余额 Balance

管理员 Admin（独立账号体系，不与 User 混用）
```

### 3.2 商品状态机

| 当前状态 | 允许动作    | 目标状态               | 触发者 |
| ---- | ------- | ------------------ | --- |
| 待审核  | 审核通过    | 已通过                | 管理员 |
| 待审核  | 审核驳回    | 已下架                | 管理员 |
| 待审核  | 卖家撤回    | 已下架                | 卖家  |
| 已通过  | 卖家下架    | 已下架                | 卖家  |
| 已通过  | 管理员强制下架 | 已下架                | 管理员 |
| 已通过  | 库存售罄    | 已下架（自动）            | 系统  |
| 已下架  | 重新上架    | 待审核（生产）/ 已通过（本地演示） | 卖家  |

**规则**：

- 只有 `已通过` 且 `is_available=true` 且库存 > 0 的商品出现在买家侧列表与搜索中。
- 本地演示模式允许"发布即通过"，生产模式必须走审核。开关为配置项 `AUTO_APPROVE_PRODUCT`，禁止在代码里硬编码。
- 商品删除为软删除（`is_deleted`），已产生订单的商品不可物理删除。

### 3.3 订单状态机

| 当前状态 | 允许动作           | 目标状态        | 触发者     |
| ---- | -------------- | ----------- | ------- |
| 待付款  | 支付成功           | 已付款         | 买家      |
| 待付款  | 取消 / 超时 30 min | 已取消         | 买家 / 系统 |
| 待付款  | 卖家改价           | 待付款（金额更新）   | 卖家（P1）  |
| 已付款  | 发货 / 约自提       | 已发货         | 卖家      |
| 已付款  | 买家申请退款         | 退款中（P1）     | 买家      |
| 已发货  | 确认收货           | 已完成         | 买家      |
| 已发货  | 超时 7 天自动确认     | 已完成         | 系统      |
| 已完成  | 评价             | 已完成（评价状态更新） | 买家      |
| 已取消  | —              | 终态          | —       |

**规则**：

- 状态只能沿上表迁移，非法迁移返回 409 并记录审计日志。
- 每次状态变更写入 `order_status_log`（操作者、前后状态、时间、备注），作为纠纷证据。
- 下单即锁定库存（`quantity -= n`），取消或超时释放；并发下单用数据库行锁或乐观版本号防超卖。

### 3.4 库存与金额

| 规则   | 说明                                             |
| ---- | ---------------------------------------------- |
| 金额单位 | 数据库存 `DECIMAL(10,2)`，禁止用 float 存钱；前端展示保留 2 位   |
| 库存扣减 | 下单扣减，取消回滚，售罄自动下架                               |
| 订单快照 | 下单时把商品名、单价、图片、卖家写入 `products_info`，后续改价不影响历史订单 |
| 总价计算 | 服务端计算，忽略客户端传的金额；运费暂为 0（校内自提）                   |
| 余额   | 余额支付需事务内扣款 + 流水记录，失败整单回滚                       |

### 3.5 审核与治理

1. **商品审核**：生产模式默认人工审核；命中敏感词（联系方式、外链、违禁词）自动转人工并标红。
2. **评价治理**：管理员可隐藏/恢复评价，隐藏后买家侧不可见，但保留数据用于申诉。
3. **用户封禁**：封禁后无法登录、无法下单，已发布商品自动下架；解封恢复。
4. **举报**：买家/卖家可举报商品或评价，进入管理后台待办列表（P1）。
5. **处置留痕**：所有治理动作写 `security` 日志与 `audit_log` 表，含操作者、对象、原因。

### 3.6 评价规则

- 仅"已完成"订单的买家可评价，每单每商品一次。
- 评分 1~5 星，内容 ≤ 500 字，支持图片（P1）。
- 评价不可编辑，可删除（软删除）；管理员可隐藏。
- 商品详情展示平均分、评价数、评分分布。

## 5. 非功能需求

### 5.1 性能与容量

| 指标 | 目标（首年） | 说明 |
| --- | --- | --- |
| 接口 P95 响应 | 读接口 ≤ 200 ms，写接口 ≤ 500 ms | 单机 4C8G，数据量 10 万商品内 |
| 首页首屏 | ≤ 2.5 s（4G 校园网） | 图片懒加载 + 压缩 |
| 并发 | 200 QPS 读、50 QPS 写 | 生产上 Gunicorn 多 worker + Redis 缓存 |
| 数据容量 | 用户 5 万、商品 20 万、订单 50 万 | 超过则分表或归档冷数据 |
| 图片 | 单张 ≤ 5 MB，上传后生成缩略图 | 生产走对象存储 + CDN |

### 5.2 安全

| 项 | 要求 |
| --- | --- |
| 传输 | 生产强制 HTTPS，HSTS；本地 HTTP 允许 |
| 密码 | werkzeug PBKDF2 哈希，禁止明文与可逆加密；注册强度校验 |
| 令牌 | JWT HS256，生产密钥必须来自环境变量，禁止默认值；有效期 7 天，支持主动失效黑名单（P1） |
| 越权 | 所有资源操作服务端校验归属；管理员接口独立装饰器 |
| 注入 | 全部走 ORM 参数化；禁止字符串拼接 SQL、禁止 `eval` |
| XSS | 用户输入输出转义；富文本白名单（P2） |
| 上传 | 校验扩展名 + MIME + 文件头；重命名存储；禁止执行权限 |
| 限流 | 登录 5 次/分钟、验证码 1 次/60 秒、下单 10 次/分钟（生产 Redis 计数） |
| 敏感信息 | 手机号在管理端脱敏展示；日志禁止记录密码、令牌、完整身份证 |
| 依赖 | 定期 `pip audit` / `npm audit`，高危漏洞 7 天内修复 |

### 5.3 可用性与容灾

- 单机部署目标可用性 99.5%；数据库每日全量备份 + binlog，保留 7 天。
- 备份恢复演练每季度一次，RTO ≤ 2 h，RPO ≤ 15 min。
- 服务健康检查 `/api/health` 返回 DB 与缓存连通状态，供负载均衡探活。

### 5.4 兼容性

| 项 | 要求 |
| --- | --- |
| 浏览器 | Chrome/Edge 最近 2 个大版本；Safari 15+ |
| 移动端 | 375 px 起自适应；核心链路（浏览/下单）移动端可用 |
| Python | 3.11+ |
| Node | 18+ |
| 数据库 | 本地 SQLite 3；生产 MySQL 8.0（或 PostgreSQL 15） |

### 5.5 可维护性

- 单文件 ≤ 400 行；单个 Vue 组件 ≤ 300 行，超出拆分。
- 禁止在业务代码中重复定义响应包装、状态枚举、错误码；统一从 `backend/constants.py`、`backend/utils/response.py` 引入。
- 所有环境差异走配置，代码中禁止出现 `if 生产:` 分支（除审核/短信这类明确开关）。
- 数据库结构变更必须提供迁移脚本，禁止依赖 `create_all` 猜结构。

### 5.6 合规

- 用户协议与隐私政策页面（P1），注册时勾选确认。
- 个人信息最小化收集：仅手机号、昵称、校区、联系方式（仅交易双方可见）。
- 提供账号注销与数据删除入口（P1）。
- 违规商品与内容的处置记录保留 ≥ 6 个月。

| 权限级别 | 普通 / 高级 / 超级 | 新建管理员默认普通 |

> **实现校对（v2.1）**：订单状态实际为 6 个，增加 `退款中`（承接 §3.3 退款流程，驳回后按 `refund_prev_status` 回退）；支付方式枚举保留 4 值，但首版 `pay_options` 只下发 **余额 / 线下**；商品另用 `is_available`、`is_featured` 两个布尔字段表达可售与运营加权，未新增状态值。

**强制约定**：状态值在前端、后端、数据库三处必须字面一致。禁止前后端各自维护一套映射后靠"猜测"对齐——这是 v1 最主要的故障来源之一。

### 6.4 迁移与种子数据

| 项 | 要求 |
| --- | --- |
| 迁移 | 使用 Alembic 管理版本；`python -m backend.dev` 启动前执行 `alembic upgrade head`，未找到 `alembic.ini` 直接报错退出 |
| 兼容 | v2.0 写的"启动自检补齐缺失列"未保留：结构变更一律走迁移脚本，旧库用 `alembic upgrade head` 或重建（本地库可删 `instance/campus.db` 后重灌） |
| 种子 | `python -m backend.seed` 灌入 **6 个平台分类、3 个轮播、3 个演示卖家、2 个买家、12 个商品、6 笔演示订单、3 条评价、1 个管理员**（手机号与密码写入 `instance/demo-accounts.txt`） |

| 幂等 | 重复执行不产生重复数据（按唯一键 upsert）；重复执行不会清空已有订单/购物车等用户数据 |

## 7. 接口规范

### 7.1 通用约定

- 基础路径 `/api`，版本化预留 `/api/v1`（首版沿用 `/api`，切换时提供兼容层）。
- 请求/响应 `application/json; charset=utf-8`；文件上传 `multipart/form-data`。
- 命名：路径用复数名词 + 短横线（`/api/seller-categories`）；JSON 字段用 snake_case。
- 时间：ISO 8601 带时区（`2026-11-20T22:00:00+08:00`），数据库存 UTC。
- 金额：字符串或两位小数数字，禁止科学计数法。

### 7.2 统一响应结构

```json
{
  "success": true,
  "code": "OK",
  "message": "操作成功",
  "data": {},
  "request_id": "8f3c9a1e"
}
```

- `success` 与 HTTP 状态码必须一致（2xx 为 true，4xx/5xx 为 false），禁止 200 包错误。
- `data` 为 `null` 时前端不得报错。
- 分页统一放在 `data` 内：

```json
{ "items": [], "total": 0, "page": 1, "per_page": 20, "pages": 0 }
```

> v1 的故障根因之一是同一语义在不同接口分别叫 `items` / `products` / `data`，前端只能逐个猜。本版**强制所有列表接口使用 `items` + `total`**，禁止别名。

### 7.3 状态码与错误码

| HTTP | code | 语义 | 前端行为 |
| --- | --- | --- | --- |
| 200/201 | OK / CREATED | 成功 | 正常处理 |
| 400 | BAD_REQUEST | 参数错误/业务校验失败 | 展示 message |
| 401 | UNAUTHORIZED | 未登录、令牌无效或过期 | 清理该身份令牌，跳对应登录页 |
| 403 | FORBIDDEN | 已登录但无权限 | 仅提示，**禁止跳登录、禁止清令牌** |
| 404 | NOT_FOUND | 资源不存在 | 展示空态或 404 页 |
| 409 | CONFLICT | 状态冲突（库存不足、非法状态迁移、重复操作） | 提示并刷新数据 |
| 422 | VALIDATION_ERROR | 字段级校验失败 | 定位到表单字段 |
| 429 | TOO_MANY_REQUESTS | 限流/锁定 | 展示剩余等待时间 |
| 500 | INTERNAL_ERROR | 服务异常 | 提示 + 展示 request_id |
| 503 | SERVICE_UNAVAILABLE | 依赖未就绪（如短信网关未配置） | 提示稍后再试 |

### 7.4 鉴权

```
Authorization: Bearer <token>
```

| 令牌类型 | 载荷 | 适用 |
| --- | --- | --- |
| 用户令牌 | `{ user_id, type: "user", exp }` | `/api/*` 用户接口 |
| 管理员令牌 | `{ admin_id, type: "admin", exp }` | `/api/admin/*` |

- 装饰器：`@token_required`（任意已登录）、`@login_required`（仅用户）、`@admin_required`（仅管理员）。
- 类型不匹配一律 403，不得返回 401。
- 登出将令牌加入黑名单（Redis，TTL 与令牌一致）——P1。

### 7.5 分页、排序、筛选

```
GET /api/products?page=1&per_page=20&tag_id=3&keyword=教材&sort=price&order=asc
```

| 参数 | 规则 |
| --- | --- |
| page | 从 1 开始，默认 1 |
| per_page | 默认 20，上限 100 |
| sort | 白名单：created_at / price / sales / views；非法值回退 created_at |
| order | asc / desc，默认 desc |
| keyword | 长度 ≤ 50，前后模糊匹配名称与描述 |

### 7.6 幂等与并发

- 下单、支付、发货、评价等写操作接受 `Idempotency-Key` 头，10 分钟内重复请求返回首次结果。
- 库存扣减使用 `UPDATE ... WHERE quantity >= n` 的行级条件更新，影响行数为 0 即库存不足。
- 前端提交按钮必须有 loading 态并禁用，防止连点重复提交。

### 7.7 文件上传

```
POST /api/uploads/image      # 通用，不依赖业务 ID
Content-Type: multipart/form-data
file=<binary>

200 { "success": true, "data": { "url": "/static/uploads/2026/11/xxx.jpg", "width": 800, "height": 600 } }
```

| 项 | 规则 |
| --- | --- |
| 类型 | jpg / jpeg / png / webp |
| 大小 | ≤ 5 MB |
| 校验 | 扩展名 + MIME + 文件头魔数三重校验 |
| 存储 | 本地 `backend/static/uploads/yyyy/mm/`；生产替换为对象存储适配器 |
| 命名 | UUID，禁止保留原文件名（防路径穿越） |

| `SEED_DEMO_DATA` | true | false | false | 演示数据 |

| `LOG_LEVEL` | DEBUG | WARNING | INFO | |

### 9.3 本地使用要求（硬性）

1. **一条命令启动**：`python -m backend.dev` 完成建库、迁移、种子、启动；`npm run dev` 启动前端。提供 `.bat` / `.sh` 各一份，且必须真正可用（v1 的一键脚本点击无效，属于交付缺陷）。
2. **零外部依赖**：本地不需要安装 MySQL、Redis、短信服务。
3. **自动补数据**：首次启动自动灌入演示数据并打印演示账号（买家/卖家/管理员）。
4. **验证码可见**：本地终端打印验证码，同时提供 `/dev/captchas` 页面，生产自动关闭。
5. **端口固定**：后端 5000，前端 8080，前端通过 Vite 代理 `/api` 到后端，避免跨域配置分歧。
6. **失败可诊断**：启动失败时输出明确原因（缺依赖/端口占用/密钥缺失），而不是堆栈。

### 9.4 生产拓扑

```
用户 → CDN(静态资源/图片)
     → Nginx(HTTPS, 反向代理, 限流, gzip)
        → Gunicorn (4 workers × 2 threads)
           → Flask 应用
              → MySQL 8（主从）
              → Redis（缓存/限流/令牌黑名单）
              → 对象存储（图片）
              → 短信网关
日志 → 本地文件 → Filebeat → Loki/ELK
监控 → /api/health 探活 + Prometheus 指标（P1）
```

| 项 | 要求 |
| --- | --- |
| 进程 | Gunicorn + gevent/threads，禁止用 Flask 内置服务器对外 |
| 静态 | `npm run build` 产物交给 Nginx/CDN，前端不做服务端渲染 |
| 上传 | 本地磁盘仅供单机；多实例必须切对象存储 |
| 密钥 | 环境变量或密钥管理服务注入，禁止写入镜像与仓库 |
| 时区 | 容器统一 `Asia/Shanghai`，数据库存 UTC，展示转本地 |
| 迁移 | 发布流程中先执行迁移再滚动重启，迁移脚本必须可回滚 |

### 9.5 上线检查清单

- [ ] `CAMPUS_CONFIG=production`，密钥为强随机且未提交仓库
- [ ] 数据库已备份，迁移脚本在预发验证通过
- [ ] HTTPS 证书有效，HTTP 强制跳转
- [ ] 演示数据与 dev 验证码页面确认关闭（访问 `/dev/captchas` 返回 404）
- [ ] 管理员注册关闭或已设置强邀请码
- [ ] 日志目录可写且磁盘余量 > 20%
- [ ] 健康检查接入负载均衡
- [ ] 回滚方案与责任人明确

## 附录 A · 从 v1 复盘沉淀的 12 条工程红线

> 这些不是"建议"，是导致 v1 返工的直接原因，写进需求作为强制约束。

1. **禁止同一语义多个字段名**（`items` / `products` / `data` 混用是 v1 头号故障源）。
2. **禁止用 401 表达"权限不足"**。401 只表示未认证，403 表示无权限。
3. **禁止任何 401 都清空登录态并硬跳转**；必须按令牌类型分别处理。
4. **禁止同一资源存在两条前端路由**（`/product/:id` 与 `/products/:id`）。
5. **禁止依赖尾斜杠重定向**：路由注册与前端调用必须字面一致，避免 308 丢失 Authorization。
6. **禁止在代码中重复定义 `json_response`、状态枚举、错误码**，必须单一来源。
7. **禁止前端猜测响应结构**；所有列表接口固定 `data.items + data.total`。
8. **禁止用 `create_all` 代替迁移**；结构变更必须有脚本且可回滚。
9. **禁止把演示开关写成代码分支**；审核、验证码、种子数据必须是配置项。
10. **禁止提交密钥**；生产缺密钥应启动失败，而不是用默认值跑起来。
11. **禁止无验证交付**；每个 P0 需求至少有一条可执行的验收断言。
12. **禁止"点一下没反应"的交付物**；脚本、按钮、入口必须真跑通再交付。
