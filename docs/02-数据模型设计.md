# 02 · 数据模型设计

## 1. 主工程现有模型（backend/models/）

| 模型 | 表 | 关键字段 | 说明 |
| --- | --- | --- | --- |
| User | users | id, quick_id, nickname, phone, password_hash, email, avatar_url, is_banned, is_deleted | 学生用户，可同时作为买家与卖家 |
| Admin | admins | id, username, password_hash, email, permission_level, login_count | 管理员独立表（普通/超级两级） |
| Product | products | id, seller_id→users, tag_id→tags, name, price, quantity, images, status(待审核/已通过/已下架), is_available, views | 商品，含审核状态与卖家归属 |
| Cart | carts | id, user_id, product_id, quantity, is_deleted | 购物车 |
| Order | orders | id, order_no, user_id, address_id, total_amount, status, products_info, 各时间字段 | 订单，含状态机 |
| Address | addresses | id, user_id, province/city/district/detail, is_default | 收货地址 |
| Tag | tags | id, name, description, is_deleted | 商品分类/标签 |
| Comment | comments | id, user_id, product_id, order_id, parent_id, content, rating, likes | 评论（含盖楼、点赞） |
| Balance | balances | id, user_id, amount, frozen_amount | 余额（含冻结） |
| Transaction | transactions | id, balance_id, amount, type, description | 余额流水 |
| Message | messages | id, user_id, content, type, is_read | 站内消息 |

设计亮点：软删除（`is_deleted`）、商品审核流、余额冻结与流水、评论盖楼，均适合校园二手交易场景。

## 3. 面向三角色的目标模型调整（设计蓝图，尚未实现）

为支撑"学生买家 / 学生卖家 / 网站管理员"，建议：

1. **统一身份体系**：将 `Admin` 并入 `users` 表，用 `role` 字段区分 `buyer / seller / admin`（或引入 `UserRole` 关联表支持一人多角色）。当前 `Admin` 与 `User` 双表 + 双套自增 ID 会导致身份混淆。
2. **学生认证字段**：给 `User` 增加 `student_no`（学号）、`campus`（校区）、`is_verified`（校园认证），确保"学生卖家"身份可信。
3. **卖家能力**：`Product.seller_id` 已具备；建议增加 `SellerProfile`（店铺名、信用分、营业执照/学生认证）、`Product.audit_status` 与审核记录表。
4. **订单按卖家拆分**：一笔订单可能含多个卖家的商品，建议引入子订单 `SubOrder`（归属卖家、发货状态），避免单订单状态无法表达多卖家发货。
5. **审核留痕**：`ProductAuditLog`（审核人、时间、结论、备注）支撑管理员治理。

## 4. 需要注意的字段不一致（当前 bug，改造时优先修复）

- `Product.tag_id` vs 路由中使用的 `category_id`
- `Product.images` vs 路由中写入的 `image_urls`
- `Order.order_no` vs 路由中使用的 `order_number`
- `Order.products_info` vs 路由中赋值的 `products`
- `created_at` vs 部分路由使用的 `create_time`
- 商品状态：模型用中文 `待审核/已通过/已下架`，部分路由用英文 `pending/approved/rejected`
