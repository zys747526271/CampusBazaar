# 01 · 架构与实现

> 对应需求：`docs/00-需求规格说明书.md`（下称 PRD）。本文说明代码怎么落地 PRD，以及有意偏离的地方。

## 1. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| Web 框架 | Flask 3 应用工厂 | PRD 指定；工厂模式便于四套环境与测试复用 |
| ORM | SQLAlchemy 2 + Flask-SQLAlchemy 3 | 参数化查询，杜绝拼接 SQL |
| 迁移 | Alembic | PRD 红线：禁止 `create_all` 管生产结构，结构变更必须可回滚 |
| 鉴权 | PyJWT（HS256） | 无状态、双令牌类型（user / admin） |
| 缓存 | Flask-Caching（本地 SimpleCache / 生产 Redis） | 验证码、限流、令牌吊销、幂等快照 |
| 图片 | Pillow | 三重校验 + 重编码去 EXIF + 生成缩略图 |
| 前端 | Vue 3 + Vite + Pinia + Vue Router | 组合式 API，按路由懒加载 |
| 样式 | 自建设计令牌 + 原生 CSS | 电商视觉可控，避免 UI 框架默认后台风；首屏体积小 |

前端不依赖组件库，`src/styles/tokens.css` 是颜色/圆角/间距的唯一来源，`base.css` 提供按钮、表单、表格、标签、弹窗等通用形态。

## 2. 分层与请求链路

```
HTTP 请求
  → Flask 应用工厂（backend/__init__.py）
      · 配置装配（config.py）
      · 扩展初始化（db / cache）
      · 日志与请求追踪（utils/logging.py：request_id、access/error/security/app 四类日志）
      · 错误处理（errors.py → 统一响应结构）
  → 蓝图路由（backend/api/**）
      · 只做参数解析、鉴权装饰器、响应包装
  → 服务层（backend/services/**）
      · 订单状态机、库存条件更新、统计聚合、定时任务
  → 模型层（backend/models/**）
```

约定：

- **路由不写业务规则**，状态迁移、库存、金额全部在 `services/`；
- **响应只从 `services/serializers.py` 取字段**，避免同一语义多个字段名；
- **错误只抛 `ApiError`**，由全局处理器渲染，禁止 `return jsonify(...), 400` 散落各处。

### 2.1 统一响应与错误

`backend/utils/response.py`：

```json
{"success": true, "code": "OK", "message": "操作成功", "data": {}, "request_id": "..."}
```

`success` 与 HTTP 状态码严格一致；4xx/5xx 时 `data` 可携带字段级错误（`{"phone": "手机号已注册"}`），前端据此定位表单。

`backend/errors.py` 提供 `bad_request / unauthorized / forbidden / not_found / conflict / validation / too_many / unavailable`，状态码与 code 一一对应。

### 2.2 日志与可观测

| 文件 | 内容 |
| --- | --- |
| `logs/access.log` | 方法、路径、状态码、耗时、IP、身份 |
| `logs/error.log` | 5xx 与未捕获异常（含堆栈） |
| `logs/security.log` | 401/403、登录失败、封禁、治理动作 |
| `logs/app.log` | 注册、发布、下单、支付等业务事件 |

- 每个请求生成 `request_id`，响应头 `X-Request-Id` 回传；
- 按天滚动 + 单文件 50MB 上限（`DailySizeRotatingHandler`），保留 14 天；
- `LOG_FORMAT=json` 输出结构化日志，便于采集到 ELK/Loki；
- 日志字段对 `password/token/code` 等键自动脱敏。

## 3. 数据模型

20 张业务表（另有 Alembic 自带的 `alembic_version`），按领域分文件：

| 文件 | 表 |
| --- | --- |
| `models/users.py` | `users` `admins` |
| `models/catalog.py` | `tags` `seller_categories` `banners` |
| `models/products.py` | `products` |
| `models/orders.py` | `carts` `orders` `order_items` `order_status_logs` |
| `models/engagement.py` | `comments` `comment_likes` `favorites` `browse_histories` `reports` `audit_logs` `messages` |
| `models/account.py` | `addresses` `balances` `balance_logs` |

关键约束：

```sql
UNIQUE (user_id, product_id)      -- carts / favorites / browse_histories
UNIQUE (order_id, product_id)     -- comments：每单每商品一次评价
UNIQUE (seller_id, name)          -- seller_categories
UNIQUE order_no                   -- orders
INDEX (status, created_at)        -- 商品列表主索引
INDEX (user_id, status) / (seller_id, status) -- 订单列表
```

### 3.1 与 PRD 的差异（有意为之）

| PRD 描述 | 实现 | 原因 |
| --- | --- | --- |
| `orders.products_info` JSON 快照 | `order_items` 明细表 | 快照语义不变（下单即固化名称/单价/图片/成色），但可被 SQL 直接统计（销量、销售额、卖家看板），避免应用层解析 JSON |
| 订单状态五种 | 增加 `退款中` | PRD 3.3 已列退款流程但未纳入枚举；单列状态才能表达"待卖家处理"的中间态，退款驳回可回到原状态（`refund_prev_status`） |
| 余额仅"支付扣款" | 增加演示充值与流水查询 | 没有入金入口时余额支付无法演示；`ENABLE_DEMO_RECHARGE` 控制，生产默认关闭 |
| 商品状态三种 | 保留 `待审核/已通过/已下架`，另加 `is_available`、`is_featured` | `is_available` 表达"售罄/主动下架"，`is_featured` 支撑首页运营加权（PRD 3.2 要求"运营加权"） |
| 举报为 P1 | 已实现商品/评价/用户三类举报 + 后台处置 | 治理闭环需要，成本可控 |
| 轮播由前端写死 | `banners` 表 + 后台维护 | PRD FR-DISC-01 要求轮播，运营需可配置 |

## 4. 状态机

### 4.1 商品

```
待审核 --通过--> 已通过 --卖家下架/管理员下架/售罄--> 已下架
待审核 --驳回--> 已下架
已下架 --重新上架--> 待审核（生产） / 已通过（AUTO_APPROVE_PRODUCT=true）
```

买家侧唯一可见口径集中在 `Product.is_on_sale`：

```python
status == 已通过 and is_available and quantity > 0 and not is_deleted
```

列表、详情、下单三处共用，避免"能搜到却不能买"。

### 4.2 订单

```
待付款 --支付--> 已付款 --发货--> 已发货 --确认收货/7 天自动--> 已完成
待付款 --取消/30 分钟超时--> 已取消
已付款/已发货 --申请退款--> 退款中 --同意--> 已取消（退款入余额）
                                 --驳回--> 回到退款前状态
```

- 迁移集中在 `services/orders.py::_transition`，任何变更写 `order_status_logs`；
- 非法迁移抛 `409 CONFLICT`；
- 下单用条件更新扣库存，取消/退款/超时回滚库存；
- `已完成` 时才累加 `products.sales`，保证"已售"与完成订单一致。

## 5. 鉴权与权限

| 装饰器 | 语义 | 失败码 |
| --- | --- | --- |
| `@token_required` | 任意有效令牌 | 缺失/过期/吊销 → 401 |
| `@login_required` | 仅用户令牌（管理员令牌拒绝） | 类型不符 → 403 |
| `@seller_required` | 用户 + 已开通卖家 | 未开通 → 403 |
| `@admin_required` | 仅管理员令牌 | 类型不符 → 403 |

- 令牌载荷：`{sub, typ: user|admin, iat, exp, jti}`；用户 7 天，管理员 12 小时；
- 登出把 `jti` 写入缓存黑名单（TTL 与令牌一致）；
- 所有权校验在服务层完成（订单、商品、地址、分类），不信任前端传入的 `user_id`；
- 管理员登录连续失败 5 次锁定 15 分钟（缓存计数），第 6 次返回 429 + `retry_after`；
- 前端拦截器只对 401 清令牌，403 仅提示——这是 PRD 附录 A 第 2、3 条的直接落地。

## 6. 并发、幂等与金额

| 问题 | 处理 |
| --- | --- |
| 超卖 | `UPDATE products SET quantity = quantity - n WHERE id=? AND quantity >= n AND status='已通过' ...`，`rowcount == 0` 即失败并回滚整单 |
| 重复提交 | `Idempotency-Key` 头 + 缓存快照（10 分钟），重放返回首次结果并带 `X-Idempotent-Replay: true` |
| 重复加购 | `UNIQUE(user_id, product_id)` + upsert |
| 重复评价 | `UNIQUE(order_id, product_id)`，服务层先查后插，双重保险 |
| 金额 | 数据库 `DECIMAL(10,2)`，服务端 `Decimal` 计算，客户端价格不参与；JSON 输出两位小数 |
| 时间 | 统一 UTC 存储，输出 ISO 8601 转东八区，前端本地化展示 |

## 7. 前端架构

- **路由**：商城 / 账户中心 / 卖家中心 / 管理后台四套布局；商品详情只有 `/products/:id` 一条路径（PRD 附录 A 第 4 条）；
- **令牌**：`cb_token`（用户）与 `cb_admin_token`（管理员）分键存储，互不覆盖；两个 axios 实例分别携带；
- **401/403**：`api/client.js` 统一处理，401 清对应令牌并跳对应登录页，403 只抛出错误由页面提示；
- **服务端驱动动作**：订单返回 `actions` 数组（`pay/cancel/confirm/refund/comment/...`），前端只渲染不判断，杜绝前后端状态机漂移；
- **设计系统**：`--brand:#FF5000`，卡片 10px 圆角，价格用等宽数字；商品图 1:1，列表用 `AppImage` 懒加载 + 骨架屏 + 失败兜底；
- **空态与错误**：`AppEmpty` 统一"插图 + 原因 + 可行动按钮"；表单错误按字段回填。

## 8. 定时任务

`services/jobs.py` 提供三个幂等函数：

- `expire_unpaid_orders`：待付款超 30 分钟自动取消并回滚库存；
- `auto_confirm_shipped`：发货满 7 天自动确认收货并累加销量；
- `mark_sold_out_products`：库存为 0 的商品置为不可售。

本地由守护线程每 60 秒执行（`ENABLE_SCHEDULER`），也可通过 `POST /api/admin/jobs/run` 手动触发（用于验收）；多实例部署时改为外部调度，函数本身无状态。

## 9. 工程红线落地对照（PRD 附录 A）

| # | 红线 | 落地位置 |
| --- | --- | --- |
| 1 | 禁止同义字段 | `services/serializers.py` 唯一 DTO；列表固定 `items/total` |
| 2 | 禁止 401 表达无权限 | `errors.py` + `utils/security.py` |
| 3 | 禁止任何 401 都清登录态 | `frontend/src/api/client.js` 按 scope 清理 |
| 4 | 禁止同资源两条路由 | `frontend/src/router/index.js` |
| 5 | 禁止依赖尾斜杠重定向 | `app.url_map.strict_slashes = False` |
| 6 | 禁止重复定义响应/枚举 | `utils/response.py`、`constants.py` |
| 7 | 禁止前端猜响应结构 | 列表统一 `data.items + data.total` |
| 8 | 禁止 `create_all` 代替迁移 | `migrations/` + `dev.py` 先迁移再启动 |
| 9 | 禁止把演示开关写成代码分支 | 全部走 `config.py` 环境变量 |
| 10 | 禁止提交密钥 | `.gitignore` + 生产缺密钥拒绝启动 |
| 11 | 禁止无验证交付 | `tests/` 31 例 + `scripts/smoke_test.py` 52 项 + `scripts/api_sweep.py` 80 请求 |
| 12 | 禁止"点了没反应" | 按钮 loading、空态、失败提示、脚本实测 |
