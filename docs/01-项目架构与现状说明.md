# 01 · 项目架构与现状说明

## 1. 当前方案概况

### A. 后端 `backend/`

- Flask 3.1 + Flask-SQLAlchemy 3.1（MySQL）+ Flask-Caching 2.5（Redis）+ Flask-CORS + 手写 JWT 鉴权（PyJWT）。
- 11 个模型，多数带 `is_deleted` 软删除；商品具备 `待审核 / 已通过 / 已下架` 状态流；余额含冻结金额与交易流水；支持推荐、图片上传安全校验、评论盖楼。
- 认证采用 JWT + 装饰器分权，`utils/` 提供鉴权、缓存、上传、推荐、支付桩等工具。
- 注意：字段 / URL / 状态枚举存在前后端系统性错配，详见 `05-已知问题与路线图.md`。

### B. 前端 `frontend/`

- Vue 3.5 + Vite 6 + Pinia 3 + Element Plus + Axios。
- 页面覆盖首页、商品详情、购物车、订单、登录注册、个人中心与若干管理页（见 `src/views/`）。
- 路由守卫与 Pinia 状态已接入，但登录态保存与角色判断仍需修复，详见 `05-已知问题与路线图.md`。

## 2. 技术选型理由

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 后端架构 | 模块化 Flask + JWT | 蓝图 / 模型 / 工具分层清晰，便于前后端分离与三角色扩展 |
| 前端架构 | Vue 3 + Vite + Element Plus + Pinia | 生态成熟、构建快，Pinia 便于角色状态管理 |
| 认证方式 | JWT + 装饰器分权 | 无状态、易于对接多端与角色权限 |
| 密钥管理 | 全部从环境变量读取 | 避免明文 `SECRET_KEY`、数据库口令、Fernet 密钥进入代码库 |
| 目录划分 | `backend/` `frontend/` `docs/` `scripts/` | 前后端独立开发，设计文档集中沉淀 |
