# 01 · 项目分析与整合说明

## 1. 两个原始项目概况

### A. demo-----（参考目录 `reference/demo-vue2-mall` + `reference/demo-flask-mallh`）

- **前端 `mall/`**：Vue 2.5 + Element UI + vue-router 3 + Axios，vue-cli 2 / webpack 3。约 24 个 `.vue` 组件、6000+ 行，含登录/注册、商城首页、商品详情、购物车、订单、个人中心、余额、VIP，以及完整的后台管理界面（商品/用户/标签/VIP/地址管理）。是两项目中**页面最完整**的一个。
- **后端 `mallh/`**：Flask 2.3 + Flask-SQLAlchemy 3 + PyMySQL + bcrypt + Flask-Migrate + Redis/Celery。13 张表、8 个蓝图、约 48 条路由，功能覆盖注册登录、购物车、订单、VIP、广告、评论、后台管理。**认证用 Session**，带迁移脚本、VIP 初始化数据与商品图片资源。
- **主要缺陷**：只有"买家 + 管理员"两角色，没有卖家；`SECRET_KEY` 与数据库口令硬编码；管理员注册接口公开；封禁字段不生效；订单状态流断裂（无"发货"接口）；前端多处接口对不上。

### B. FlaskWebProject（主工程来源）

- **后端 `backend/`**：Flask 2.3 + SQLAlchemy + Flask-Caching + CORS，**手写 JWT 鉴权 + 装饰器分权**。11 个模型，多数带 `is_deleted` 软删除；商品有 `待审核/已通过/已下架` 状态流；余额含冻结金额与交易流水；有推荐算法、图片上传安全校验、评论盖楼等较新的设计。**模块化程度更高**，因此选为主工程后端底座。
- **前端 `frontend/`**：Vue 3.3 + Vite 4.5 + Pinia + Element Plus + Axios。页面定位就是"校园二手商品交易平台"，含首页、商品详情、购物车、订单、登录注册、个人中心与 4 个管理页，页面规模同样完整。
- **主要缺陷**：字段/URL/状态枚举前后端系统性错配（如 `category_id` vs `tag_id`、`order_number` vs `order_no`、中文状态 vs 英文状态）；`requirements.txt` 缺多个实际依赖；无迁移与种子数据；管理员体系因枚举与整数比较而失效；`payment.py`/`notification.py` 在 import 时访问 `current_app` 会崩溃。

## 2. 整合决策

| 维度 | 决策 | 理由 |
| --- | --- | --- |
| 后端底座 | 采用 FlaskWebProject 的模块化 Flask + JWT 结构 | 蓝图/模型/工具分层清晰， JWT 更适合前后端分离与三角色扩展 |
| 前端底座 | 采用 FlaskWebProject 的 Vue 3 + Vite + Element Plus | 定位已是"校园"，技术栈更现代，Pinia 便于角色状态管理 |
| demo 代码 | 原样保留在 `reference/`，不并入主工程 | 保留页面与功能参考价值，避免 Vue 2/Vue 3、Session/JWT 两套体系互相污染 |
| 密钥 | 全部改为环境变量读取 | 原项目存在明文 `SECRET_KEY`、数据库口令、Fernet 密钥，必须清理 |
| 目录 | 统一 `backend/` `frontend/` `docs/` `scripts/` `reference/` | 便于后续独立开发与文档沉淀 |

## 3. 已完成工作

1. 克隆两个仓库至本机，并完整静态分析其技术栈、模型、路由与问题。
2. 建立统一项目骨架，复制主后端与主前端源码，清理 `node_modules`、`venv`、`__pycache__` 等冗余（体积由 ~190 MB 降至 ~12 MB）。
3. 密钥安全化：`config.py` 改为环境变量注入；`miyao.py` 改为随机密钥生成器；移除所有硬编码口令。
4. 修复 `payment.py`、`notification.py` 的导入期崩溃（Redis 改为惰性初始化）。
5. 补齐 `requirements.txt`、`.env.example`、`.gitignore`、`LICENSE`、统一入口与 README。
6. 编写本文档及 5 份设计/分析文档，明确三角色改造方向。
