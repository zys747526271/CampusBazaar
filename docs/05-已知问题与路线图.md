# 05 · 已知问题与路线图

## 1. 阻塞运行的问题（需优先处理）

1. **依赖不全**：初始 `requirements.txt` 只列 4 项，实际还需 `flask-cors`、`PyJWT`、`cryptography`、`redis`、`PyMySQL`、`requests`。本仓库已补齐。
2. **外部服务强依赖**：MySQL 未启动则 `db.create_all()` 失败；Redis 未启动则验证码/缓存/评论接口 500。部署前需准备这两个服务（快速冒烟可用 `CAMPUS_CONFIG=testing` 免外部服务）。
3. **配置键缺失**：`ENCRYPTION_KEY` 此前未定义，调用身份证加解密会 `KeyError`。已在 `config.py` 改为环境变量注入。
4. **SQLAlchemy 3.0 分页 API 变更**：多处 `Model.query.paginate()` 参数需为关键字参数，当前调用方式已核验符合 3.x 要求，但仍建议统一迁移到 `db.paginate()`。
5. **前端 `crypto.js` 依赖 `fernet` 包但 `package.json` 未声明**（当前为死代码，可先移除或补依赖）。

## 2. 前后端错配（功能无法真正跑通）

- 商品：`category_id` ↔ `tag_id`；`image_urls` ↔ `images`；状态 `待审核/已通过/已下架` ↔ `pending/approved/rejected`。
- 订单：`order_number` ↔ `order_no`；`products` ↔ `products_info`；状态英文 ↔ 中文枚举。
- 路径：admin/order/tag/message 蓝图路由内重复前缀，导致前端 `api.js` 调用的路径 404。
- 响应结构：后端统一 `{success,message,data}`，前端多处按 `{data:{products}}` 解包，实际是 `{data:{items}}`。
- 登录：前端 LoginPage 未保存 `userInfo`，导致管理员判断与路由守卫失效。

## 3. 安全与权限

- 关闭/加审批：管理员注册接口。
- 修复 `super_admin_required` 的枚举与整数比较。
- 移除日志中的密码、token、验证码明文打印。
- 将 Redis 中的用户对象 pickle 缓存改为 JSON，避免反序列化风险。
- 生产配置强制校验关键密钥（`ProductionConfig.validate()` 已提供，需在启动时调用）。

## 4. 校园三角色落地（分阶段）

- **阶段一：数据层**——统一用户表与 `role` 字段；增加学号/校区/认证字段；增加 `SellerProfile`、`SubOrder`、`ProductAuditLog`。
- **阶段二：权限层**——统一 JWT 载荷；完善装饰器与路由守卫；关闭公开管理员注册。
- **阶段三：业务流**——商品发布→审核→上架→购买→分单→发货→收货→评价的完整链路，补"发货"接口。
- **阶段四：运营**——轮播广告、VIP/会员、数据统计、消息通知。

## 5. 建议的下一步动作

1. 准备 MySQL（建库 `campus_bazaar`）与 Redis，复制 `.env.example` 为 `.env` 并填好配置。
2. 用工具 Python 建 venv 并安装 `requirements.txt`，启动后端验证 `/api/health`。
3. 前端 `npm install && npm run dev`，先打通登录/注册与商品列表。
4. 按第 2 节清单逐项对齐前后端字段与路径。
5. 按第 4 节阶段推进三角色改造。
